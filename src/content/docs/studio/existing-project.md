你在 Codex、Claude Code 或其他 Agent 里已经做了一个 HyperFrames 项目，希望到桌面应用里边看边改。可以打开同一个项目文件夹继续工作，不必把成片当作新素材重新制作。

这里有一个重要前提：应用与外部工具可能操作的是同一份文件。导入项目不等于复制备份，交接时需要让下一位 Agent 了解已经发生的修改。

## 从应用打开已有文件夹

应用的 Import projects 会列出发现的项目，你可以导入其中一个。项目在其他位置时，可以通过 File → Open Folder 打开，或将文件夹拖到侧边栏。具体键盘提示按操作系统显示为准。

打开以后先确认预览和素材属于预期项目，而不只看列表名称。相近名称的多个文件夹容易混淆；确认目录后，再开始改字或移动片段。

## 从 Agent 交接与普通打开有何区别

固定官方来源描述了 Mac 上从 Agent 会话执行 open 的交接方式：项目在应用里打开，对话也能延续。普通终端打开则可能是新对话；Windows、Linux 及未安装应用时的行为不同，不能照搬 Mac 的会话延续承诺。

因此，“项目打开了”和“之前的对话已接续”应分开确认。如果没有历史上下文，简要说明当前目标、已经认可的部分和这次只要改什么。

## 回外部工具前，让它先了解变化

官方交接中的 catch-up 会列出应用内发生的请求与文件变化，让原 Agent 接着工作；它有会话交接条件，普通导入不能据此假定已有同样记录。

无论使用哪种方式，都应避免下一轮沿着旧版本的理解直接重写。下面是表达示例，没有实际打开项目：

> 继续这个项目。先确认我在应用中改过的标题位置和结尾停留，只补字幕，不重做已确认的场景。无法读取交接记录时先检查当前文件。

## 交接完成后验证什么

先看标题、素材和字体是否完整，再定位到你刚改过的时刻。移动目录或缺失文件都可能影响预览，不能把“列表里出现了项目”当作验证完成。

需要选择创作工具，读 [连接 Agent](/studio/connect-your-agent/)；需要理解恢复范围，读 [保留修改与恢复](/mechanisms/history/)；准备在应用里修改，读 [工作区](/studio/workspace/)。
