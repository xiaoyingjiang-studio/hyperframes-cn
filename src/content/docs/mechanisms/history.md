可编辑项目会经历多轮修改。真正重要的不是每次都从头生成，而是知道当前版本包含什么、哪些是你已经做好的改动，以及这次失败后怎样回到可靠的起点。

官方公开流程同时涉及桌面应用的撤销、Agent 运行的撤销，以及 CLI 的项目历史。它们关联到不同操作，不能把其中一个入口当成所有环境都相同的恢复按钮。

## 修改之前先确认当前版本

如果你刚在应用里移动了标题，再让外部 Agent 继续编辑，它需要先读取这些变化。否则可能依据旧的理解重写文件，把手动调整当成待修复内容。官方的交接流程会提供应用中发生的请求和文件变化，供 Agent 接着工作。

因此交接时说“在当前版本基础上继续，先了解我刚才的改动”，比重新描述一遍完整视频更清楚。任务范围也应说明，例如只处理结尾，不重做开场。

## 应用里的两类撤销

桌面应用支持撤销与重做，聊天中的每次 Agent 运行也有自己的 Undo。你刚拖错一个片段，与刚接受一整轮 Agent 修改，是不同范围的动作；恢复前先确认要撤回的是哪一种。

CLI 的公开 skill 还描述了记录工作、读取用户变化及撤销的历史方法。具体命令以当前版本为准，不能因为看过历史说明就假定任意旧项目都已经有完整记录。

## 失败时怎样保留有用的信息

如果第三次修改让标题更糟，先保留发生了什么：改的是哪一场、修改前后有什么差别、哪一版曾经正确。能够恢复时回到确认过的版本，再缩小修改范围，比连续要求“再好一点”更容易找到原因。

下面是表达示例，没有执行历史操作：

> 撤回刚才这一轮对第二场景的修改，保留我之前手动调整的产品图。确认回到标题完整可见的版本后，只处理字幕遮挡，不再改变场景布局。

## 交接时保留项目与素材

输出视频适合播放，恢复和继续修改需要项目及引用文件。应用与外部工具可能操作同一目录，打开项目也不必然意味着已经复制了一份备份。重要版本应有明确的保存和交接方式。

如何在应用与外部 Agent 间继续工作，见 [打开已有项目](/studio/existing-project/)；想理解具体能保留哪些结构，见 [可编辑项目与素材](/mechanisms/editable-project/)。
