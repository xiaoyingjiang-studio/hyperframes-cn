已经用 Remotion 或其他工具做好的动画，怎样接进 HyperFrames，还能保留多少修改能力？remotion-to-hyperframes skill 帮助 Agent 选择迁移方式，并把迁移后的画面与原作品比较。名字提到 Remotion，但官方也覆盖其他浏览器动画和能够输出视频的工具。

首先决定你要继续修改什么。想改每个标题，与只想裁切整段动画，需要保留的结构不同，成本和验收方法也不同。

## 三种迁移方式对应三种编辑粒度

| 方式 | 怎样进入项目 | 之后主要能改什么 |
| --- | --- | --- |
| 原生重建 | 转成 HTML 与时间轴动画 | 单个元素、变量和场景内容 |
| 托管运行 | 保留原代码，由 HyperFrames 提供时间 | 整体时序、位置和暴露的参数 |
| 媒体导入 | 先输出视频，再作为片段使用 | 裁切、摆放与叠加，不能拆开像素里的元素 |

例如一段标题动画能原生重建，就有机会继续换文字；复杂浏览器图形可以保留代码但接管时间；依赖实时物理、网络或墙上时钟的内容，则需要先变成媒体。不能只因为“已导入”就承诺一切都可编辑。

## 原生重建为什么还要逐帧比较

原工具可能以帧数表示时间，HyperFrames 的相关场景属性使用秒。换算错误会让转场提前或延后；字体、边框和布局模型的差异也可能让静态画面变化。因此迁移不是把 API 名称换一遍就结束。

官方要求先识别不能直接翻译的代码，再在每个场景和切点附近对照，最后比较输出成片。无法保留的声音变化、字体替换和近似处理应单独记录，不能藏在“迁移成功”里。

## 给 Agent 的输入要包含原来的样子

准备原工程、必要素材和一份可对照的原片，并说明优先保留哪些修改能力。只有截图，可以帮助对照某一帧，却不能证明整段运动和声音一致。

## 看交付时同时问两个问题

第一，画面和时间与原作相比改变了什么？第二，之后在哪里、以什么粒度继续改？要求交付说明列出每个部分的方式和对照结果，比一句“已经转换”更有用。
