CLI 是通过命令操作项目的入口。你可以把它理解成一组明确的动作：新建、查看、检查、抽帧、预览和导出。hyperframes-cli skill 告诉 Agent 在什么阶段用哪个动作，以及失败后怎样读结果；它并不代替你决定视频应该讲什么。

如果你在桌面应用里创作，不需要为了理解这页先打开终端。这些操作也帮助你区分“项目能打开”“某几帧正常”和“最终视频已经验证”之间的差别。

## 一次制作怎样经过这些工具

先读取项目和时间轴，知道哪些场景在什么时候出现；修改后检查结构与运行状态；再抽取画面，确认标题、主体和素材确实可见。预览用于观看与继续修改，render 才会生成交付文件。这些步骤各自回答不同的问题，不能用一次命令成功概括全部质量。

例如，自动检查没有报错，但抽帧里产品图太小，接下来应调整布局；如果预览正常而输出文件没有声音，则应检查导出后的媒体，而不是重新生成整个故事。

## 读懂检查结果比记住命令更重要

官方说明，检查中的布局和对比度审计可能被尚未解决的结构错误阻挡。因此“0 samples”表示没有检查到样本，不能读成“零问题”。失败输出中的 Fix 提示用于指出下一步；JSON 结果方便程序读取，但仍要看字段表达的实际状态。

抽帧解决的是“指定时刻到底画了什么”。应覆盖每个场景和修改处，而不只挑开场一张好看的图片。导出后还要确认文件非空、时长和尺寸符合项目，并查看解码后的画面。

## 修改已有项目时先保留现场

时间轴编辑可以移动、裁切、拆分片段，也有批量应用与撤销机制。官方 skill 还要求 Agent 在动手前读取用户自上轮以来的修改，沿着已有工作继续。如果某次修改让结果变差，历史记录比凭印象手工改回去可靠。

可以这样给 Agent 下任务。这是表达示例，没有执行命令：

> 先读取项目和我最近的修改，只延长结尾品牌画面的停留。检查场景边界，给我看修改处的抽帧和预览；确认后再导出，不重写其他场景。

## 什么时候看其他指南

安装和实际命令从 [CLI 快速开始](/start/cli/) 进入，以当前安装版本的帮助为准。素材生成属于 [media-use](/skills/media-use/)；模块查找属于 [registry](/skills/hyperframes-registry/)。本页解释正式发布 skill 的工作分工，不把 CLI 的版本当成桌面应用的版本，也不把列出的操作说成本环境已经实测。
