设计师交给你一份 Figma 文件，你想把其中的标志、产品界面和分镜做成视频。这里最先要决定的是：你需要一张素材、一组能继续修改的元素，还是几个状态之间的运动？这三种目标需要不同的处理方式。

figma skill 是给创作 Agent 的工作说明，帮助它把设计内容接入 HyperFrames。它不是“贴上链接就能一键还原动画”的承诺，也不能据此判断你的 Studio 桌面版本一定有同名按钮。

## 先说清要保留什么

假设要做一个品牌开场：标志必须原样保留，卡片上的标题需要改字，最后从卡片展开到产品界面。标志适合作为 SVG 或 PNG 素材导入；卡片如果还要改文字、颜色和布局，就需要导入为可编辑 HTML；品牌颜色和字体则可以作为共享的设计变量使用。变量可以理解为统一的设置，多个地方引用同一个值，修改时就不必逐个找颜色。

因此，给 Agent 文件链接时，也要指出具体节点和用途。“使用这个文件”没有说清它应该拿哪些内容、哪些必须保真、哪些允许重新设计。

## 从设计稿到可渲染的项目

官方 skill 将导入安排在制作阶段，保存本地文件，并在项目的媒体记录中保留来源。最终渲染使用这些本地内容，不在每一帧重新访问 Figma。这样也意味着：设计稿后来改了，不等于已有视频自动跟着更新，需要重新导入相应内容。

素材、品牌变量和组件通过带授权的接口获取；动效信息需要 Figma 连接器或用户提供的原生导出。需要令牌时，由你自己在环境变量或项目配置中设置，不要把它粘贴进聊天。文件地址正确但账号无权访问，仍然无法读取。

## 为什么三张分镜不等于三页幻灯片

如果三张设计帧里都有同一张卡片，只是卡片从小变大、从左移到中间，那么它们描述的是同一个元素随时间变化的状态。制作时需要解释状态之间怎样运动，而不是把三张截图依次播放。产品界面的连续状态还可能需要重建“移动光标—点击—界面响应”的过程。

可以这样说明需求。以下是表达示例，没有实际调用 Figma：

> 用这个节点的标志和配色做品牌开场。标题改成“让想法动起来”。三张分镜中的卡片是同一个对象：先从左侧进入，再放大，最后展开成产品界面。标志保持原样，标题和卡片要能继续编辑。

## 导入以后检查什么

先把关键画面与 Figma 导出的图片对照，看字体、换行、比例和位置是否一致；再检查运动过程。静态帧相似不能证明动画相似。官方还说明着色器导出存在限制，需要原生图片或视频作为素材，不能笼统承诺所有设计效果都可编辑还原。

如果失败，先分清是令牌失效、授权范围不足，还是账号看不到文件；如果只是文字偏移，先核对字体和文本排版。涉及其他媒体的获取，继续读 [media-use](/skills/media-use/)；想选择合适的 skill，回到 [Skills 与创作工具总览](/learn/skills/)。
